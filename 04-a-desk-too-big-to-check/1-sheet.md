# A Desk Too Big to Check

Objective: after this, you can explain why reachable states multiply as workers and loans are added (state explosion), move a spec's sizes into CONSTANTS set in the `.cfg` with model values, use a SYMMETRY set built from `Permutations` for safety checks and say why not for liveness, recognise an unbounded counter as the reason a model never finishes, make it finite by a bound in the spec, by deleting it, or by a CONSTRAINT, name the assumption each adds and what a constraint silently cuts, read TLC's "states left on queue" before trusting "No error has been found", and state the small-scope hypothesis with its limits.

Terms (new in this lesson; constant, generated, distinct, queue, weak fairness, lasso and stuttering step are recaps from lessons 1 to 3, not new):
- state explosion: the number of reachable states grows exponentially, multiplying by a roughly fixed factor with each worker, loan or value added.
- depth: how far from the start the breadth-first search has reached, counted as the number of states on the longest path (one more than its steps; TLC prints 4 for a 3-step chain); a finished run ends with 0 states left on queue, a stopped one does not.
- model value: a value TLC invents for a run, equal only to itself and comparable only for equality; used for workers, loans and placeholders (Nobody, NoLoan).
- permutation: a renaming of a set's members among themselves.
- symmetry reduction: declaring that renamings never change what can happen, so the checker keeps one representative state per group (`SYMMETRY Perms`, `Perms == Permutations(Workers) \union Permutations(Loans)`).
- unbounded counter: a variable that can grow without limit; it makes the reachable states infinite.
- state constraint: a formula about one state named on a CONSTRAINT line; TLC checks the invariant on a generated state that breaks it but takes no step from it.
- small-scope hypothesis: the empirical observation that most design bugs show up in some small instance; not a theorem, and the instance must contain the bug's shape.

Misconception: "No error has been found means it passed." Why wrong: a stopped run prints it with about 5,000 states left on queue (4,983 in the logged `Big.cfg` run), and a constraint run prints it with 0 left after cutting the bug away (`FloristBudget.cfg`, 232 states, the 5-step bug unseen).
Second misconception: "bigger models are safer." Why wrong: the no-key bug is the same 3 steps at 1 × 1, 2 × 2 and 3 × 3 (8, 23, 62 states); the florist bug needs a shape (two loans on one account), not size.
Third misconception: "symmetry is a free speed-up." Why wrong: it is sound only for interchangeable members (model values help guarantee this) and only for safety; TLC warns for liveness, so check liveness without it.
Fourth misconception: "a constraint is a cheaper way to write a bound." Why wrong: a constraint gives the same distinct count as the guard (8,218) but hides behaviors past the cut, including the unbounded spec's lose-forever liveness violation.

Concept check, answers (never shown to the learner):
1. Not finite. In NoCount a repeated lost reply was a stuttering step because nothing changed; now each one increments attempts[l], so every lap is a new state (snippet 1's argument). It also breaks liveness: a Lost step now changes a variable, so it counts as Work under weak fairness, and a worker may lose replies forever without sending, so ClaimLeadsToPaid fails in the spec (an infinite non-repeating behavior; not run in TLC, reasoning). Best fix: delete it (nothing reads it; the dashboard is not the spec's job), which restores NoCount (197 states at 2 × 2, 5,167 at 3 × 3). A bound (attempts[l] < N in Lost) adds "at most N lost replies per loan". A CONSTRAINT hides the lose-forever behavior and TLC warns with liveness. Full marks for asking "who reads it?" and for seeing that the variable turned harmless stutters into real steps.
2. No. The invariant names L4471 and L4472, so loans are no longer interchangeable for what is being checked; with loan renamings in Perms, a state where the order is violated can be stored as its renamed twin, where the formula reads differently. Keep `Permutations(Workers)` only (1,527 states at 3 × 3, `SymWorkers.cfg`), since the invariant treats workers alike. TLC does not detect this misuse (general knowledge, not demonstrated; see Assumptions).
3. Any two: a CONSTRAINT cut the bug (FloristBudget: 232 states, bug one step past the cut); the scope lacked the bug's shape (FloristOneVan: 727 states, no second florist loan); a deleted counter or a bound hid an assumption (lose-forever replies); symmetry on a liveness check; the invariant itself is too weak (NoDoublePayout passes the unpaid florist van, which needs PaidMeansMoney).
